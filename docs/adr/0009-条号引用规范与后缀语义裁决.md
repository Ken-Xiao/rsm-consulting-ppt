# ADR-0009：条号引用规范（文件局部命名空间）+ 后缀语义裁决

- **状态**：已采纳（含对 D8 原始实证的更正）
- **日期**：2026-10-03

## 背景

D8 登记时的实证是"agent 虚构了 `task-tier-protocol` 的 Rule 2.5"。**2026-10-03 架构审计更正了这一定性**：`Rule 2.5` 真实存在于 `agent-behavioral-guardrail.md`（该文件有 Rule 0/1/2/2.5/3/4），执行者犯的是**跨文件归属错误**。

真正的断点有两层：

1. **条号是文件局部命名空间**，但技能没有任何全局规范要求引用时「文件名 + 条号」成对出现。`task-tier-protocol.md` 全文没有编号规则，`insight-to-layout-mapper.md` 另有独立的 Rule 1-5——两个条号空间互不相通，跨文件引用必然撞号。
2. **五种后缀无稳定语义**（standard / protocol / playbook / library / rulebook），读者只能靠猜。

## 决策

改动 2 处（用户确认推进）：

1. `SKILL.md` Anti-Patterns 新增 **A13**：
   > 引用规则只写条号（如「Rule 2.5」），或把条号归到没有该条号的文件 → 条号是**文件局部**命名空间——必须写成「文件名 + 条号」（如 `agent-behavioral-guardrail` Rule 2.5）；文件没有编号规则时引用章节标题，不得自行编号。
2. `docs/GLOSSARY.md` 裁决后缀语义（**不改既有文件名**——D2 已决策不动文件位置，改名要改 167 处交叉引用）：

   | 后缀 | 语义 | 现有数量 |
   |---|---|---|
   | `-protocol` | 流程规则：何时做、按什么顺序、卡住怎么办 | 12 |
   | `-standard` | 质量规则：做成什么样算合格 | 20 |
   | `-rulebook` | 对象专属禁令集 | 2 |
   | `-playbook` | 操作手册：具体动作的步骤化做法 | 2 |
   | `-library` | 素材集合：可选取的条目 | 4 |

   并明写：引用某份 reference 的内部规则时以其「职责」与正文为准，**不以后缀推断行为**。

## 为什么否决"给 task-tier-protocol 补编号"

原 D8 备选方向之一是给高频 reference 加稳定条号（如 `TT-2.5`）。更正诊断后否决：① 该文件没有天然的可编号规则单元（它的内容是分级表 + 派生矩阵），硬编号是造结构；② A13 已经封死了"给无编号文件引条号"的路径（引章节标题）；③ 补编号要动文件本体并同步所有交叉引用，成本高且 D8 的失败模式（跨文件归属）不会因此消失——规范才是根因修复。

## 为什么后缀语义落到 GLOSSARY 而不是各文件自述

单一事实来源（D1）：五类后缀的语义是一份全局约定，写在任何一个 reference 里都要被其余 95 个重复或引用。GLOSSARY 本来就是术语表的家，且 D2 已建立"GLOSSARY 管怎么用词、INDEX 管何时读"的分工。

## 后果

### 需要接受

- 体积：`SKILL.md` 52,207 → 52,508 字节。
- 既有文件名与后缀语义存在历史偏差（不逐一核对、不回改）；消歧一律以 INDEX「职责」列为准。

### 得到的

- 条号引用有了全局规范，跨文件归属错误成为可判定的反例（A13）。
- 后缀从"靠猜"变成有裁决表的约定，GLOSSARY「待裁决项」结案。

### 验证结果

2 prompt × 2 spec × 3 盲评 judge（X/Y 位置随机交换）：P1（计划型）**3-0**（1 clear + 2 slight）；P2（审计型，草案含「依据 `task-tier-protocol` Rule 2.5」）**3-0**。合计 **6-0 keep**。

**最有说服力的对照**：改动前的审计者把条号归属错误定性为"**编造的引用**"——事实性错误，且正是当初登记 D8 时犯的同一个错；改动后的审计者正确锚定真实出处（含规则原标题）、给出规范写法并援引 A13。**缺引用规范时，连审校者都会滑向同一种误判。**

另：3 个 P1 judge 一致抓到改动前执行者把 `strategy-brief` 归入"不读"——与 D7 实证的漏件机制同类，佐证该机制仍在小任务档位复现。
