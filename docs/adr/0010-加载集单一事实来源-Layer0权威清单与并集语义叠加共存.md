# ADR-0010 · 加载集单一事实来源：Layer 0 权威清单与并集语义的叠加共存

- 状态：已采纳（含验证后修正）
- 日期：2026-10-03
- 关联：ADR-0007（Decision Router 下限改名与并集注）、ADR-0008（读路由表 ≠ 激活能力）、DEBT「A 轮」节、经验 D5（第三实例）

## 背景

漏件方差 ×3 的结构性根因：「每任务必读集合」散落 4 处表述（progressive-loading-protocol Layer 0 的 4 件、SKILL.md Core Workflow「第一步必须读」3 件、跨阶段三件套、INDEX 第 0 组并集注），执行者引用任何一处较弱表述即可"合法"排除文件。D7（并集注）与架构审计（INDEX 行补强）是逐点止血；本轮做结构性收敛。

## 决策

1. **progressive-loading-protocol 的 Layer 0 升级为「每任务必读唯一权威清单」**：9 文件（原 Layer 0 三件 + guardrail + Core Workflow 第一步三件 + 跨阶段三件套去重），逐件标注理由与出处。
2. **裁决规则**：其他文件的必读表述只做指针/触发说明；任何文件、任何 INDEX 行不得用于把清单成员排除出加载集；修改必读规则只改此清单，并全库搜「必读」同义行同步指针。
3. **宿主选择**：Layer 0 属跨阶段三件套，任务开始时必在上下文中——权威必须在加载决策发生时可用（tier-stage-matrix 在定档后才读，不能当权威宿主）。
4. **其余四处降为指针**：SKILL.md Decision Router 并集注、Key References 段、INDEX 加载纪律行与第 0 组注。

## 验证中发现的稀释效应与修正（重要）

第一轮配对验证 P2（client-ready）0-3 反对：改动版执行者以 Layer 1「Load only when entering stage」把 9 个下限件全部推迟出加载计划——新的权威框架稀释了 ADR-0007 的并集语义。这是 **D5 模式第三次出现**（新增绑定/权威条款未声明与既有硬要求的权重关系）。

修正：权威段落显式声明**管辖边界**——

> 本清单裁决的是「每任务必读」的成员资格，不改变 Decision Router 的并集规则：本轮加载计划 = 本清单 ∪ Decision Router「阶段必需（下限）」列 ∪ 触发件；下限件按 stage 排期但必须逐件列入计划；Layer 1 Anti-Pattern 只约束视觉/语言/场景类按需件。

复采样（全新执行者 + judge）P2r 3-0 支持改动。最终 keep。

## 被否决的方案

- **把权威清单放进 tier-stage-matrix**：该文件定档后才读，任务开始的加载决策发生时它不在上下文中，无法行使权威。
- **同时改写 Decision Router 下限列的语义（下限=可排期）**：混改两个维度，破坏配对验证的归因能力；且 D7 的并集语义刚验证过，应保留。

## 教训

1. 引入「唯一权威」类框架时，同轮必须显式声明它**不改变**哪些既有语义（这里是并集、降级、底线），否则新的权威叙述会盖过旧锁——即使旧锁刚在上一轮验证过。
2. judge 标签互换会让票型完全失真（表面 2-1，实为 3-0 反向）：票型与预期方向相反时，先对照执行者原文核实每条事实归属，再决定复采样或修工件。
