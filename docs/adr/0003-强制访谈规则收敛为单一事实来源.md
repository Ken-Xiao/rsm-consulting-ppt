# ADR-0003：强制访谈规则收敛为单一事实来源

- **状态**：已采纳
- **日期**：2026-10-03

## 背景

darwin rubric 逐维诊断显示，本 skill 最弱的两维之一是**维度 7「整体架构」（权重 12，得 4 分）**，主要扣分源是"强制访谈"规则在 `SKILL.md` 中重复出现。

核查结果：该规则共出现在 **22 处**。分类后：

| 类别 | 处数 | 性质 |
|---|---|---|
| 规则正文（First Response Contract） | 4 | 应保留 |
| stage 名引用（Decision Router 表格的 `I0-forced-interview → ...`） | 5 | 应保留 |
| 非确认信号清单 | 1 | 独特信息，应保留 |
| 确认状态机机制（CN 节点推进） | 2 | **不同机制**，应保留 |
| Invocation Examples 的流程步骤 | 3 | 示例完整性，应保留 |
| **重复的规则正文** | **6** | **应改指针或删除** |
| 其他（frontmatter、流程步骤引用） | 1 | 保留 |

原判断"重复 6 处以上、可压缩 2-3KB"**高估了冗余量**。逐处核对后发现多数出现位置携带独特信息。

## 决策

1. **First Response Contract 是强制访谈规则的唯一规则正文。** 其他位置只能**引用**它，不得复述规则内容。
2. **只删除真正冗余的 6 处**，不动携带独特信息的位置：
   - Decision Router 后说明：删去与 First Response Contract 重复的两点，**保留非确认信号清单**，并把 Core Workflow §2 里的"之前已经聊过类似项目"合并进来。
   - Core Workflow §2 末条：删除（与非确认信号清单重复）。
   - Non-Negotiables / Always：改为指向 First Response Contract，**保留"4-8 个确认问题"这一具体参数**。
   - Non-Negotiables / Express：删去共同前提，**保留 tier 差异部分**（可跳过完整深度访谈和逻辑 gate、保留基础 QA）。
   - Non-Negotiables / Quick-Polish：删除整条（与 Always 重复）。
   - Non-Negotiables / Client-Ready：删去共同前提，**保留 `direct_build_after_minimal_interview` 标记要求**。
3. **tier 差异必须保留在 Non-Negotiables 中。** Express / Quick-Polish / Client-Ready 三节讲的是"执行深度可以降到哪"，不是"要不要访谈"，不属于重复。
4. **保留 3 个 Invocation Examples 中的流程步骤。** 示例的价值在于展示完整流程，删掉会削弱示例的示范作用。

## 被否决的方案

- **只保留 First Response Contract，其余全部改指针（原方案 A）**：否决理由：会删掉 tier 差异、确认状态机机制和示例流程步骤，损失大于收益。
- **不删，只统一措辞（原方案 C）**：否决理由：维度 7 的失分不解决。
- **把 Non-Negotiables 整节压缩成一张表**：否决理由：该节是"每个 tier 的验收清单"，表格化会损失判据的可读性；且超出本轮"去重"的范围。

## 后果

### 需要接受

- **压缩量远小于预估**：654 字节（47,898 → 47,244），而非预估的 2-3KB。**这是正确的代价**——真正冗余的只有 6 处，其余是必要信息。
- **仍存在 19 处提及**，但性质已从"规则正文重复"变为"引用"。维度 7 的改善主要体现在**结构清晰度**而非体积。
- **去重后可能削弱 fail-closed 行为**。原重复出现可能起到了"强化权重"的作用。风险与验证方式见下。

### 得到的

- 规则有了明确的单一事实来源，改一处不会漏改。
- 原 DEBT D1 的"可压缩 2-3KB"判断被证伪，避免后续轮次继续按错误预估做决策。

### 验证要求

必须用「用户说跳过提问、直接生成」的 prompt 做 paired 验证，确认去重后**仍然 fail-closed**（停在访谈、记录 `direct_build_after_minimal_interview`）。这是本轮唯一的真实风险点。
