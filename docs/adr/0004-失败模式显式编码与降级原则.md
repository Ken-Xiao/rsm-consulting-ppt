# ADR-0004：失败模式显式编码，确立「降级只降工具不降标准」原则

- **状态**：已采纳
- **日期**：2026-10-03

## 背景

darwin rubric 逐维诊断显示，本 skill 最弱的两维之一是**维度 3「失败模式编码」（权重 12，得 4 分）**。rubric 明确规定：**"只写正向流程而不写失败分支扣 ≥3 分"**。

核查结果：

| 检查项 | 结果 |
|---|---|
| `SKILL.md` 内是否有「如果 X 失败 → Y」分支 | 几乎没有。仅两处边缘情形（"Fail closed：如果不确定是否已经完成访谈"、"确认节点未通过时必须停止"） |
| 是否有失败处理文件 | 有 `auto-fix-playbook.md`，但它只覆盖**审校发现问题后**的返修顺序（事实/逻辑/决策/呈现/语言/polish） |
| 是否覆盖**流程卡住**（材料不足、工具不可用、用户拒绝、节点未通过） | **不覆盖** |
| 是否有"降级原则" | **完全没有** |

对照：`writing-style` v1.2.0 已有成熟的 `references/failure-modes.md`（11 条 + 核心原则"降级只能降执行工具，不能降判断标准"）。本 skill 缺这一层。

## 决策

1. **新增 `references/failure-modes.md`**，15 条失败模式，四列结构：**触发条件 / 一线修复 / 仍失败兜底 / 不可降的底线**。四列结构比三列多出的"底线"列是关键——它让每条降级动作都有对应的不可让渡项。
2. **确立核心原则：降级只能降「执行工具」，不能降「判断标准」。**
   - 可降：换执行工具（脚本 → 手工核）、缩小范围（全 deck → 关键页）、延后非关键 stage。
   - 不可降：来源可追溯、口径声明、建议可执行、字号不低于 minimum、确认节点的通过条件、结论强度与证据的匹配。
3. **降级必须显式声明**，并规定记录格式（降级项 / 降了什么 / 未降什么 / 残余风险）。禁止把降级结果当作完整结果交付。
4. **`SKILL.md` 加一节「Failure Modes And Degradation」**：核心原则 + 5 条高频触发速查表 + 指向细则。速查表明确标注"细则见该文件，不要只按本表执行"。
5. **与 `auto-fix-playbook.md` 的分工写进两份文件**：本文件管流程卡住，auto-fix-playbook 管审校发现问题后的返修顺序。

## 被否决的方案

- **只在 `SKILL.md` 内嵌失败分支，不建 reference（原方案 C）**：否决理由：15 条分支内嵌会把 SKILL.md 推高约 4KB，且失败处理是"低频但必须可查"的内容，适合下沉。
- **只加路由，SKILL.md 不列具体分支（原方案 B）**：否决理由：失败模式的触发是**实时判断**，需要速查表支持；且 rubric 要求"显式编码失败模式"，只给路由可能不被视为显式编码。
- **复用 `auto-fix-playbook.md`，不新建文件**：否决理由：两者触发时机不同（审校后 vs 流程中），混在一起会让"返修顺序"和"降级动作"互相干扰。分文件但互相引用更清晰。
- **照搬 writing-style 的三列结构**：否决理由：writing-style 是文本处理 skill，其"判断标准"相对单一；RSM 是生产管线，"底线"因阶段而异（字号、来源、确认条件各有各的底线），需要独立成列。

## 后果

### 需要接受

- **SKILL.md 体积增加约 1.2KB**（47,244 → 48,468）。加上 D1 省下的 654 字节，本轮净增 570 字节（47,898 → 48,468，101.2%）。这是"补上缺失能力"的合理代价。
- **速查表与 reference 全表存在 5 条内容重叠**。这是刻意的：速查表是索引，全表是规则。已通过"细则见该文件，不要只按本表执行"的措辞降低误用风险。**若后续发现该措辞不足，应改为只留路由、不列条目**（与 ADR-0003 的单一事实来源原则一致）。
- **15 条覆盖是否完整未经实战检验**。首次实战遇到未编码的失败情形时，应补充进表。

### 得到的

- 流程卡住时有了明确动作，不再依赖临场判断。
- "降级只降工具不降标准"这条原则是本 skill 此前**完全没有**的，它防止了"因为工具不可用所以标准放宽"这一常见退化路径。
- 维度 3 从"未编码"变为"显式编码 + 有原则 + 有记录格式"。
