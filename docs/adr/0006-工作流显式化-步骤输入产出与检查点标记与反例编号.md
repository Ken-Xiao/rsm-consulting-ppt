# ADR-0006：工作流显式化——步骤输入产出、检查点标记、反例编号

- **状态**：已采纳
- **日期**：2026-10-03

## 背景

darwin rubric 逐维 triage（DEBT D3）留下三个未登记弱项，取证结果：

| 弱项 | 权重 | 失分 | 取证 |
|---|---:|---:|---|
| 维度 2 工作流输入/产出 | 12 | 3.6 | Core Workflow 7 步只写"读哪些 reference"；`输入` 在整段出现 **0 次**；22 项中间产物被压成一坨平铺列表放在 Non-Negotiables/Pipeline，未映射到步骤 |
| 维度 4 检查点显性标记 | 6 | 2.4 | `🔴`/`🛑`/`⛔`/`STOP`/`❌` **全部 0 处**；停点散在 4 处正文 |
| 维度 9 反例与黑名单 | 6 | 2.4 | **无任何反例小节**；禁令散落 **57 处**（`不得` 35、`不要` 8、`避免` 7、`不能` 6、`禁止` 1） |

**关键发现**：`confirmation-state-machine.md` 已有标准的 `Node | Input artifact | Required output | Confirmed status` 表——输入/产出模式在 CN 节点层已解决，只是**没下沉到 Core Workflow 步骤层**。这决定了修法是"对齐既有范式"，而不是新造结构。

## 决策

三项全做（用户 2026-10-03 确认），并额外做一处去重：

1. **维度 2**：Core Workflow 7 步各加一行「**输入** → **产出**」，产出一律给具体中间产物名，与 `confirmation-state-machine` 的 State Nodes 对齐。
2. **维度 4**：Core Workflow 开头新增「检查点速查」表（5 行：CN0/CN1/CN2/CN3 + stage gate，列「位置 / 通过条件 / 未通过时」）；在 4 处真正的强制停点加统一**文本**标记 **【硬停】**（不用 emoji，与文件现有纯文本风格一致）。
3. **维度 9**：新增「Anti-Patterns（高频反例速查）」小节，12 条稳定编号（A1-A12），每条带「正确做法」，并明写**「本表是速查，不是全集」**。
4. **附带去重**：删除 Non-Negotiables/Pipeline 里那份 22 项中间产物平铺清单（已被 Core Workflow 各步「产出」覆盖），改指向 Core Workflow；把唯一遗漏的 `reference_layout_profile.json` 补进第 5 步。

## 为什么反例表只列 12 条、且必须写"非全集"

散落禁令有 57 处。**全部集中迁移会违反 D1 确立的单一事实来源**（删改散落处会牵动多个章节，且新增集中表后两处必然漂移）。故采用与 `failure-modes` 相同的成熟做法：**集中列最高频、最致命的一批 + 明写非全集**。

## 被否决的方案

- **反例全部集中迁移**：违反单一事实来源，牵动面大。
- **检查点用 emoji（🔴/⛔）标注**：`SKILL.md` 全文目前零 emoji，引入会与文件风格不一致；且 emoji 在不同渲染环境下可读性不稳。
- **只加集中表、正文不加标记**：正文扫读时仍看不到停点，维度 4 的失分只解决一半。

## 后果

### 需要接受

- **体积净增**：`SKILL.md` 45,992 → 51,410 字节（原始基线 112.6%）。增的都是非冗余内容，且同时删掉了一处重复清单。
- **反例表与散落禁令并存**：靠"非全集"声明与 A 编号区分——集中表是入口，散落处是完整规则。

### 得到的

- 7 步各有可执行的输入/产出定义，且产出即 `pipeline` 档的中间产物清单（单一口径）。
- 5 个硬停点集中可查，13 处正文标记可扫读。
- 12 条反例有稳定编号，可被审校、交付说明和后续争议裁决引用。

### 验证结果

2 个请求 × 2 spec × 3 独立盲评 judge：P1（执行计划 + 反例清单）**3-0 clear×3**；P2（停点判断）最终 **3-0 slight×3**。**合计 6-0 → keep**。

### 验证过程中的一次反转（重要）

P2 第一轮跑出 **2-1 支持改动前版本**。追查后拆成两个原因：

1. **评测工件缺陷**：我写的摘要版漏掉了 `direct_build_after_minimal_interview`，原输出里两版都有。
2. **真实的稀释效应**：新增的检查点表只写了禁止项，**挤掉了 `failure-modes` F6 的降级后果**（"不得声称 `client-ready`"）。3 个 judge 一致指出改动后版本的降级路径不完整。

修正工件 + 在检查点表下补写降级段（并加一句"停点表列出的禁止项不替代这一降级记录要求"）后，重跑执行者与 judge → 3-0。

**这是 D5 的第二次出现**，且形态不同：D5 是"绑定外部规范没声明叠加/替代"，本次是"速查表没声明与细则的关系"。同一根因——**局部内容的权重边界没写清**。已记入 D5 的第二实例。
