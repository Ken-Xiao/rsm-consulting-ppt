# Failure Modes And Degradation Paths

本文件是**流程卡住时的操作细则**，任何 tier、任何 stage 都可能触发，必须能读到。

与 [auto-fix-playbook](auto-fix-playbook.md) 分工：本文件管**流程卡住**（材料、工具、确认、资源不可用），auto-fix-playbook 管**审校发现问题后**的返修顺序。

**失败不许静默跳过；降级只能降执行工具，不能降判断标准。** 降级必须在交付说明中显式声明：降了什么、为什么、残余风险是什么。禁止把降级结果当作完整结果交付。

## 失败模式表

| # | 触发条件 | 一线修复 | 仍失败兜底 | 不可降的底线 |
|---|---|---|---|---|
| F1 | 用户拒绝访谈，或写「跳过提问，直接生成」 | 走最小访谈，确认跳过意图、修改范围和风险接受 | 记录 `direct_build_after_minimal_interview` 并在交付说明中标注未确认风险 | 不得无交互开工；未记录不得进入构建 |
| F2 | 引用的 `references/` 文件读不到 | 跳过该文件，用 `SKILL.md` 对应硬约束替代 | 交付说明中列出缺失 reference 及替代依据 | 判断标准不得随之放宽 |
| F3 | 材料不足以支撑结论 | 缩小范围，只做材料支撑得住的部分 | 输出需补充的材料清单，等用户提供 | 不得编造数字、来源、机构名、日期 |
| F4 | 关键数字缺来源，或两处口径不可比 | 回原始材料核对；口径不同则并列标注 | 降级为「待验证事项」或从结论中删除 | 不得用二手来源顶替；不得把不可比写成可比 |
| F5 | 用户否定了已确认的框架 | 回退到 `CN1_framework`，重新确认核心问题与总答案 | 明确告知：框架变更会使已产出页面失效，需重新评估范围 | 不得在已被否定的框架上继续加页 |
| F6 | 确认节点未通过，但用户要求继续 | 停止并说明未通过的具体判据 | 只有用户显式接受该风险才可推进，且必须记入 `confirmation_log.json` | 确认节点的通过条件本身不得下调 |
| F7 | HTML 预览无法生成（环境/依赖不可用） | 用结构说明 + 关键页静态描述替代 | 标记 `preview_unavailable` 并取得用户确认 | 未取得确认不得进入批量构建 |
| F8 | 图表数据缺失或无法回链到 `chart_data/` | 换用可回链的证据对象 | 该图降级为示意并显式标注「示意，非实测」 | 不得作为客户交付的核心图表 |
| F9 | 字体/图片资源不可用 | 在**当前 profile 与用户视觉锁内**找替代方案 | 记录替代项与视觉偏差，交用户确认 | 不得静默换字体；用户明确指定过的字体锁不得回退 |
| F10 | PPTX 渲染与已确认的 HTML 定稿不一致 | 以 HTML 定稿为准修正 PPTX | 无法对齐时列出偏差清单，请用户裁定 | 不得反向修改已确认的 HTML |
| F11 | 页数超出预算 | 拆页、合并同类项、移入附录 | 与用户确认页数预算调整 | 不得靠缩小字号或压缩内容突破 minimum |
| F12 | 审校发现 `critical` 问题而工期不足 | 修复 `critical` 后再交付 | 显式降档交付（如 `client-ready` → `partner-ready`），说明未修复项 | 不得带 `critical` 声称 `client-ready` |
| F13 | 排版审计脚本/无头浏览器不可用 | 手工逐页核对溢出、越界、同行卡片高度 | 在交付说明中声明「未做程序化审计」 | 声明不等于免检；关键页仍需人工核对 |
| F14 | 用户要求在 `quick-polish` 中新增分析结论 | 说明该请求超出 `quick-polish` 范围 | 升档到 `partner-ready` 或 `client-ready`，补相应 gate | 不得在 `quick-polish` 档位下新增未经验证的结论 |
| F15 | 语域判定有歧义（例如不确定该用 consulting 还是 strict） | 按更严的一档处理 | 交付说明中注明所用语域与判定依据 | 语域判定不得靠猜；判错等于规则方向判错 |

## 降级记录格式

交付说明中必须包含：

```text
降级声明：
- 降级项：[F# + 触发条件]
- 降了什么：[执行工具 / 范围 / 时序]
- 未降什么：[对应的判断标准]
- 残余风险：[用户需要知道的具体影响]
```

**降级只能降「执行工具」，不能降「判断标准」**：脚本不可用就手工核，reference 缺失就用硬规则兜，预览不可用就用结构说明替代——但来源可追溯、口径声明、建议可执行、字号不低于 minimum 这些标准不因工具受限而放宽。
