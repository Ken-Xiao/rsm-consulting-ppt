# Decision To Deck Attribute Map

用于把用户回答转成可执行的 PPT 属性。所有完整生成、整体优化、客户交付、pipeline 项目都应在 `brief.json`、`framework_confirmation.md`、`storyline_map.json` 或 `preset_map.json` 中记录这些锁定结果。

## Core Principle

用户每个选择至少要锁定一个具体属性，例如：

- 受众语气
- 信息密度
- 核心信息出现频次
- 章节结构
- 风险处理方式
- 页数预算
- 视觉破格范围
- 样章检查点
- 批量产出节奏

如果某个问题不会改变 PPT 属性，就不要问。

## Phase 1 · Strategy

### Q1.1 核心决策者

| 用户选择 | Deck attributes |
|---|---|
| 一把手 / 业务负责人 | 强化业务价值、ROI、对标和授权事项；技术细节下沉附录。 |
| 三方联席评审 | 强化方法论、治理结构、角色分工、协作机制。 |
| 一线试点 | 强化工作流、案例、用户旅程、操作细节。 |
| 管理层 / 战略层 | 强化战略意义、差异化定位、资源投入和路线图；Core Message 至少在执行摘要、中段承接页、收尾页出现。 |
| 监管/合规 | 强化规则依据、边界、证据链、风险缓释；少用激进判断。 |
| 投委会 / 投资人 | 强化回报、情景、估值、风险、退出或不行动后果。 |

### Q1.2 汇报场景

| 用户选择 | Deck attributes |
|---|---|
| 30-45 分钟现场讲解 | 演讲式低密度；大字、留白、单页单观点；通常 15-25 页。 |
| 60 分钟现场 + 会后传阅 | 混合式；每页可讲可读；图表+解释+来源完整；通常 25-45 页。 |
| 邮件/网盘传阅 | 阅读式高密度；每页自洽；解释更完整；需要更多来源脚注和附录。 |
| 路演/对外沟通 | 强化主张、可信证据、视觉节奏；减少内部过程信息。 |

### Q1.3 核心说服目标

| 用户选择 | Deck attributes |
|---|---|
| 批准短周期 POC | 加 POC 范围卡、试点边界、预算/资源页、成功指标。 |
| 立项长周期项目 | 加 12-18 个月路线图、治理结构、培训/运营机制、阶段交付物。 |
| 识别风险/审慎决策 | 加风险矩阵、控制动作、触发阈值、不可行边界。 |
| 投资/交易决策 | 加估值、情景、敏感性、交易结构、退出/不行动后果。 |
| 教育理解某概念 | 增加方法论破题、对比表、案例化解释，减少硬结论强度。 |

### Q1.4 风险态度

| 用户选择 | Deck attributes |
|---|---|
| 弱化风险 | 风险放附录或答辩备忘；正文聚焦机会。 |
| 适度提示 | 正文 1 页风险与边界，配缓释动作。 |
| 主动直面 | 独立风险章节；至少“难点页 + 应对页”两页对称结构；编号一一对应。 |

## Phase 2 · Substance

### Q2.1 Core Message

Agent 必须先给出一句 Core Message 供用户修剪：

```text
我先把这份材料的核心信息压成一句话：[暂定 Core Message]。
请确认这是准确、偏强、偏弱，还是需要换重心？
```

| 用户反馈 | Deck attributes |
|---|---|
| 完全准确 | 锁定 Core Message，执行摘要、中段承接页、收尾页复用。 |
| 方向对但词要换 | 替换关键词，主轴不变。 |
| 重心换到另一维度 | 回到 Phase 1 检查受众/目标是否判断错。 |

### Q2.2 研究深度

| 用户选择 | Deck attributes |
|---|---|
| 只用用户材料 | 不新增外部事实；缺口标“待补充/待确认”。 |
| 补公开背景数据 | 只查监管、公告、年报、行业报告等权威背景；每个数据点有来源。 |
| 做同业/案例研究 | 增加 benchmark、案例页、对标图表和来源血缘。 |

### Q2.3 数字精度

| 用户选择 | Deck attributes |
|---|---|
| 严格待补 | 不编估算；未知数字用 `待基线/待确认`。 |
| 公开数据可用 + 内部数据待补 | 外部公开数据可入正文；内部专有指标标待确认。 |
| 区间估算 | 只在 KPI/情景页使用区间；必须标“估算供讨论”，并用独立色彩语义。 |

## Phase 3 · Structure

### Q3.1 页数

| 用户选择 | Deck attributes |
|---|---|
| 10-15 页决策版 | 只保留总答案、关键证据、建议和风险。 |
| 20-30 页管理层版 | 保留章节结构、核心分析和行动计划。 |
| 40+ 页深度报告 | 保留完整证据链、方法论、专题页和附录。 |

### Q3.2 叙事框架

| 用户选择 | Deck attributes |
|---|---|
| SCQA | 情境 → 复杂化 → 问题 → 答案。 |
| 矛盾-证据-行动 | 先提出矛盾，再逐章证明，最后落行动。 |
| 反差-诊断-跃迁 | 适合“账面好但市场/客户不认可”。 |
| 风险-穿透-建议 | 适合尽调、合规、风险审查。 |
| 三重拐点 | 监管/行业/自身三股力量共同解释“为什么是现在”。 |

### Q3.3 案例或证据深度

| 用户选择 | Deck attributes |
|---|---|
| 完整保留 | 用 4-6 页做流程/案例/用户旅程；允许关键页破格。 |
| 压缩 | 2-3 页展示关键镜头。 |
| 附录化 | 正文只留总览，细节入附录。 |

### Q3.4 风险页位置

| 用户选择 | Deck attributes |
|---|---|
| 收尾前 | 1 页风险与边界 + 1 页下一步。 |
| 中段 | 风险作为诊断后的约束条件。 |
| 独立章节 | 风险作为可信感高峰，必须配缓释机制。 |

## Phase 4 · Surface

### Q4.1 模板保留度

| 用户选择 | Deck attributes |
|---|---|
| 100% 沿用 | 保持母版、页眉页脚、布局，不做破格页。 |
| 80% 保留 + 关键页破格 | 保持主视觉 DNA，封面/章节/案例/驾驶舱/行动页可破格。 |
| 只借颜色 | 结构重做，颜色/字体保留。 |

### Q4.2 品牌签名

| 用户选择 | Deck attributes |
|---|---|
| 完整品牌签名 | 页脚写完整项目名、版本、日期、机构。 |
| 低调 | 页脚只写“内部讨论稿 · N/总页数”或客户要求格式。 |
| 多方联署 | 封面/收尾页保留多方名称或签字区域。 |

### Q4.3 封面策略

| 用户选择 | Deck attributes |
|---|---|
| 原模板背景 | 最安全，保持模板一致性。 |
| 纯色几何 | 最稳重，适合监管/合规。 |
| 中性素材 | 使用行业/建筑/金融场景图，需来源或生成记录。 |
| AI 生成 | 必须用户确认；记录 `image_prompt`、`image_role`、`style_profile`。 |

### Q4.4 样章节奏

| 用户选择 | Deck attributes |
|---|---|
| 先 3 张样章 | 封面 + 数据页 + 关键案例/破格/行动页，默认推荐。 |
| 1 张样章 | 只适合很小项目；视觉风险较高。 |
| 跳过样章 | 仅在用户明确要求或内部草稿时允许；记录风险。 |

## Phase 5 · Execution

### Q5.1 批量节奏

| 用户选择 | Agent behavior |
|---|---|
| 一鼓作气 | 批量生成后统一 QA。 |
| 分批给我看 | 每 8-16 页一批，等待通过后继续。 |
| 先关键页 | 先做封面、执行摘要、章节页、关键证据页和行动页。 |

### Q5.2 细节修正授权

| 用户选择 | Agent behavior |
|---|---|
| 细节自调 | Agent 最终统一修 1-2 轮，不再逐项追问。 |
| 保持样章 | 样章成为视觉基准，后续不得偏离。 |
| 指定修改 | 只改用户列出的细节。 |

## Output Schema

建议在 `brief.json` 或 `framework_confirmation.md` 中增加：

```json
{
  "interaction_locks": {
    "audience_weight": "strategy / execution / governance / compliance / investment",
    "information_density": "presentation / hybrid / reading",
    "persuasion_goal": "approve_poc / approve_project / educate / decide_transaction / identify_risk",
    "risk_posture": "hide / moderate / confront",
    "research_depth": "materials_only / public_background / benchmark_research",
    "number_precision": "strict_pending / public_ok_internal_pending / range_estimate",
    "page_budget": "decision_10_15 / management_20_30 / deep_40_plus",
    "narrative_frame": "SCQA / contradiction_action / gap_diagnosis_leap / risk_drilldown_recommendation / triple_inflection",
    "template_retention": "100 / 80_plus_breakout / color_only",
    "sample_checkpoint": "three_samples / one_sample / skipped",
    "batch_cadence": "full_batch / segmented / key_pages_first"
  }
}
```
