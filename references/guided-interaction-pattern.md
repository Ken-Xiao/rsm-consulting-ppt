# Guided Interaction Pattern

用于把 PPT 生成从“一次性猜测”升级为“阶段式确认”。本文件适用于新建、整体优化、整体升级、重构、复刻风格、客户正式交付、董事会/管理层/投委会汇报，以及用户反馈“没有交互确认”的情况。

## Core Principle

**提问 = 锁定 PPT 属性。**

Agent 不是把决策权完全推给用户，而是把散乱材料翻译成结构化选择题，让用户只拍板少数高杠杆判断；其他部分由 agent 用专业默认值兜底。

## Full Interaction Chain

标准完整项目采用 5 个阶段、每轮 1-4 题、约 5-6 轮往返：

```text
Round 1 · Phase 1 Strategy
  -> 锁定受众、场景、目标、风险态度
Round 2 · Phase 2 Substance A
  -> 锁定 Core Message、研究深度
  -> agent 执行必要的材料读取/公开研究/事实池整理
Round 3 · Phase 2 Substance B + Phase 3 Structure A
  -> 锁定数字精度、页数、叙事框架、案例/证据深度
Round 4 · Phase 3 Structure B
  -> 确认章节框架、风险页位置、附录/交付物
Round 5 · Phase 4 Surface
  -> 锁定模板保留度、品牌签名、封面策略、样章检查点
Round 6 · Phase 5 Execution
  -> 样章确认、批量节奏、修正授权
```

小项目可以压缩为 Quick Mode，但仍必须先问 4-8 个问题并等待回答。不能把完整 15 个问题一次性丢给用户。

## Question Design Rules

1. **每问加推荐选项**：用 `[A]` `[B]` `[C]`，并用“推荐”标出默认专业判断。
2. **每轮最多 4 题**：用户疲劳阈值通常在 5 题。
3. **共享阶段前缀**：如 `Q1.1 决策者 / Q1.2 汇报场景 / Q1.3 目标 / Q1.4 风险态度`。
4. **少问开放题**：不要问“你想要什么风格”，改问“[A] 保险财务报告风 [B] 实践分享风 [C] 克制白底咨询风”。
5. **问题标题用名词短语**：`汇报场景` 比 `你希望在什么场景汇报？` 更易扫读。
6. **每个选项写清影响**：告诉用户这个选择会改变哪些页面或风格。
7. **下一轮必须回显影响**：用户选了某项后，下一轮说明“我已据此锁定 X”。

## Default Question Set

### Phase 1 · Strategy

每个完整项目必须覆盖：

1. **核心决策者**：董事会 / 管理层 / 投委会 / 监管合规 / 外部客户 / 内部项目组。
2. **汇报场景**：现场讲解 / 现场 + 会后传阅 / 邮件传阅 / 路演。
3. **核心说服目标**：批准方案 / 识别风险 / 确认交易结构 / 立项 / 投资决策 / 沟通同步。
4. **风险态度**：弱化风险 / 适度提示 / 主动直面并配应对。

### Phase 2 · Substance

1. **Core Message 锁定**：agent 先写一句暂定核心信息，让用户修剪，不让用户从零创造。
2. **研究深度**：只用用户材料 / 补公开背景数据 / 做同业对标或政策研究。
3. **数字精度**：严格待补 / 公开数据可用、内部数据待补 / 区间估算并标注“供讨论”。

### Phase 3 · Structure

1. **总页数**：10-15 页决策版 / 20-30 页管理层版 / 40+ 页深度报告。
2. **叙事框架**：SCQA / 矛盾-证据-行动 / 反差-诊断-跃迁 / 风险-穿透-建议 / 三重拐点。
3. **案例或证据深度**：完整保留 / 压缩 / 附录化。
4. **风险页位置**：收尾前 / 中段 / 独立风险章节 / 难点+应对对称页。

### Phase 4 · Surface

1. **模板保留度**：100% 沿用 / 80% 保留 + 关键页破格 / 只借颜色和组件。
2. **品牌签名**：完整品牌签名 / 低调页脚 / 多方联署 / 客户母版。
3. **封面策略**：原模板背景 / 纯色几何 / 中性专业素材 / AI 生成图片。
4. **样章节奏**：先 3 张样章 / 只 1 张样章 / 跳过样章。

### Phase 5 · Execution

1. **样章方向**：确认 / 方向对但细节自调 / 需要重做视觉方向。
2. **细节修改授权**：agent 自行统一修 / 每批确认 / 只修用户指出的问题。
3. **批量节奏**：一鼓作气 / 每 8-16 页一批 / 只先做扉页和关键转折页。

## User Fatigue Handling

| User signal | Agent behavior |
|---|---|
| `都行 / 你看着办 / 随便` | 选择推荐项，并说明“我按 [B] 推进，如不合适随时叫停”。 |
| 用户连续选首项 | 下一轮把推荐项放到非首项，验证用户是否真的在选择。 |
| 选项组合冲突 | 用一句话点明冲突，遵从最近一次选择，不无限追问。 |
| 用户问“还要多久” | 不再开启新问题，进入执行或给出剩余阶段表。 |

## Sample Chapter Checkpoint

客户交付版或视觉不确定项目，正式批量构建前默认做 3 张样章：

1. **封面**：验收颜色、字体、品牌签名、整体气质。
2. **数据/图表页**：验收信息密度、图表权威感、来源脚注。
3. **关键案例/破格页/行动页**：验收视觉记忆点和特殊结构是否成立。

3 张样章代表主要视觉语言。除非用户特别要求，不少于 3 张，也不多于 3 张。

## What To Report Back

每轮用户回答后，必须用 2-4 句回显：

```text
我已据此锁定：
- 受众语气：[...]
- 信息密度：[...]
- 风险处理：[...]
- 对 PPT 的影响：[新增/删除/调整哪些章节或页面类型]
```

不要只说“收到”。要让用户看到每个选择如何改变 PPT。

## Anti-Patterns

- 用户已回答的问题又重复问。
- 把方法论术语塞进问题，如“本体论对象图采用 ER 图还是 UML 图”。
- 在要求确认后同一回复继续生成页面。
- 样章 manifest 写了 40 页，但 body 只有 3 页，就说“骨架完成”。
- 用户选择主动直面风险后，只做一页泛泛的“风险提示”。
